# Implementation — 0. Overview

This document series describes how the *microfun* implementation works
internally: how source text becomes a running program, how lazy evaluation is
realized, and how the runtime represents and reduces values. It is a companion
to [LANGUAGE.md](LANGUAGE.md), which defines the language itself; here we are
concerned with *mechanism* rather than *meaning*.

The execution engine is a single **spineless tagless G-machine**. Source is
lexed and parsed into a pure AST; the AST is resolved and lowered into a **Core
IR** that makes laziness explicit (every deferred computation is a thunk, every
function a closure with an explicit capture list); the Core is compiled to a flat
bytecode; and the G-machine reduces the program body to weak head normal form,
printing whatever the program's side-effecting builtins emit along the way.

Correctness is pinned by golden tests: `tests/cases` holds a `*.expected`
(stdout) and `*.exit` (exit code) file for every case, and `tests/run.sh` checks
the engine's output against them.

## Pipeline overview

Running a program proceeds through six stages, orchestrated by `main`
([main.go](../main.go)):

```
source ─Lex─► tokens ─Parse─► AST ─Resolve+Lower─► Core ─Compile─► Bytecode ─Run─► value
                              (pure)   (names, slots,    (flat      (G-machine)
                                        capture, desugar,  []Instr)
                                        explicit thunks)
```

1. **Lex** ([lexer.go](../lexer.go)) turns the source bytes into a flat slice of
   tokens, discarding whitespace and comments.
2. **Parse** ([parser.go](../parser.go)) builds an abstract syntax tree from the
   tokens by recursive descent. The AST is *pure* — no later pass writes back to
   it (see [2.Parser](2.Parser.md)).
3. **Resolve** ([resolve.go](../resolve.go)) walks the tree to resolve every
   name, rejecting undefined and duplicate names and unimported modules. It
   produces *resolution facts* (which definition each use refers to) without
   mutating the AST (see [3.Resolver](3.Resolver.md)).
4. **Lower** ([lower.go](../lower.go), [core.go](../core.go)) turns the resolved
   AST into the Core IR: names become addressing modes (local slot, upvalue slot,
   module slot), frame slots are assigned, closures get a minimal capture list,
   operators / lists / strings / list-patterns are desugared, and every lazy
   position becomes an explicit thunk. Module bindings the program never reaches are
   dropped here as dead code, so only the working set is compiled (see
   [4.Core IR and Lowering](4.Core%20IR%20and%20Lowering.md)).
5. **Compile** ([compile.go](../compile.go), [bytecode.go](../bytecode.go))
   translates the Core into one flat `[]Instr` array; every body (program, module
   binding, lambda case, thunk) is a PC-addressed span (see
   [5.Bytecode and Compiler](5.Bytecode%20and%20Compiler.md)).
6. **Run** ([machine.go](../machine.go)) reduces the program body on the
   G-machine: an explicit reduction stack of argument and update frames, push/
   enter application, and thunk forcing by running compiled bodies (see
   [6.The G-machine](6.The%20G-machine.md)).

Modules referenced by `import` clauses are loaded, parsed, and resolved before
execution begins; lowering then compiles only the bindings the program actually
reaches.

Each stage fails loudly and early: a lexical or syntactic error prints a located
diagnostic and exits before the next stage runs; the resolver collects *all* name
errors before exiting; only the G-machine produces errors at run time.

## Inspecting the stages

The intermediate representations can be dumped as text rather than run, which is
useful for understanding (or debugging) what each pass produced:

| Flag              | Emits                  | Extension |
| ----------------- | ---------------------- | --------- |
| `--dump-ast`      | the parsed AST         | `.ast`    |
| `--dump-core`     | the lowered Core IR    | `.ir`     |
| `--dump-bytecode` | the compiled bytecode  | `.bc`     |

Each dump is an indented, human-readable rendering — not a serialization meant to
be read back, but a complete picture of the information that stage holds:

- The **AST** dump (`dumpast.go`) shows structure and literal values exactly as
  parsed, with no resolution or slot information, because none exists yet.
- The **Core** dump (`dumpcore.go`) shows what lowering decided: every name as an
  addressing mode (local/upvalue/module slot), every lazy position as a thunk with
  its update flag and frame size, every lambda with its frame size and free-
  variable capture list, and the desugaring of lists, strings, and list patterns.
- The **bytecode** dump (`dumpbytecode.go`) disassembles the flat `[]Instr` array
  in PC order, printing a header at every span entry (the program body, each module
  binding, each closure and thunk template) and decoding operands against the
  constant, name, and module pools.

Flags can be combined. Any dump flag switches off execution: the requested stages
are emitted and the program is not run. With `--to-file`, each active dump is
written to a sibling of the input file with the extension above (so
`microfun --dump-core --to-file prog.mf` writes `prog.ir`); otherwise dumps go to
stdout.

The **AST** dump shows every imported module's bindings in full, because the AST is
a faithful picture of the source. The **Core** and **bytecode** dumps show only the
module bindings the program actually reaches: lowering drops unreferenced bindings
as dead code (see stage 4 below), so they are never lowered or compiled in the
first place.

## Runtime services

The runtime representation — the `Value` tagged union and the heap types — lives
in [value.go](../value.go) and is shared by everything downstream of the machine:
`show`/`peek` rendering ([show.go](../show.go)), structural equality and
full-normal-form forcing ([equal.go](../equal.go)), the lazy stdin streams
([stdin.go](../stdin.go)), the numeric/comparison prim kernels
([prims.go](../prims.go)), the structural builtins ([builtins.go](../builtins.go)),
and error reporting ([errors.go](../errors.go)). Because a weak-head-normal-form
result is an ordinary `Value`, all of these are written once against `Value` and
used directly.

## Source positions

Every token and AST node carries a `SourcePos` ([lexer.go](../lexer.go)):

```go
type SourcePos struct {
    File   *Source // the file the span belongs to
    Start  int     // byte offset of the first character
    Length int     // length of the span in bytes
}
```

Two positions in the same file can be joined with `a.To(b)`, which produces the
span reaching from the start of `a` to the end of `b`. This is how a node computes
its own extent from its children, and how positions thread through lowering and
the bytecode's position pool so a *runtime* error can still point back at the
exact sub-expression that caused it.

`Log(msg, pos, severity)` is the single diagnostic routine used everywhere. It
recovers the line and column from the byte offset, prints the offending source
line, and underlines the span in colour.
