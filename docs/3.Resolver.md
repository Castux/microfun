# Implementation — 3. Resolver

The resolver ([resolve.go](../resolve.go)) is the first semantic pass. It walks
the pure AST, decides what every name refers to, and reports the compile-time
errors microfun has: a use with no definition, a duplicate binding in one scope,
and a reference to a module that was not imported. It does **not** mutate the AST
(the AST stays pure, see [2.Parser](2.Parser.md)); instead it returns a set of
*resolution facts* keyed by the AST `*Name` / `*QualifiedName` nodes, which the
lowerer ([4.Core IR and Lowering](4.Core%20IR%20and%20Lowering.md)) reads.

## Output: the resolution facts

```go
type Resolution struct {
    Errors int
    Uses   map[*Name]ResolutionFact      // each name use → what it resolves to
    Quals  map[*QualifiedName]*Binding   // each module.name → the bound binding
}

type ResolutionFact struct {
    Kind   ResolveKind // ResolveLocal | ResolveModule | ResolveBuiltin
    Def    Node        // the defining *Binding or *Name; nil for builtins
    Module *Module     // set when Kind == ResolveModule
}
```

`Uses[name]` answers, for every name *occurrence* that is a use (not a binding),
the three questions the lowerer needs:

- **`ResolveBuiltin`** — a primitive (`add`, `peek`, …) or the input streams
  `stdin`/`bstdin`. `Def` is nil; the lowerer maps the name to its `Builtin`
  value (or, for the streams, to the prebuilt lazy list).
- **`ResolveModule`** — a name brought into scope by `import`. `Def` is the
  module's `*Binding` and `Module` is the owning module; the lowerer turns it into
  a module-environment slot reference.
- **`ResolveLocal`** — a let binding or a lambda-pattern variable. `Def` is the
  defining `*Binding` (for a let) or `*Name` (for a pattern), which the lowerer
  uses as the key to the frame slot it assigned.

`Quals` does the same job for qualified `module.name` references, mapping each to
the public binding it names.

## Scopes

A `scope` is a name → defining-node map tagged with the AST node that owns it. The
resolver keeps a stack of scopes and resolves a name by scanning from innermost to
outermost — ordinary lexical scoping. The owning node's type tells the resolver
the resolution kind: a `nil` owner is the builtin scope (`ResolveBuiltin`), a
`*Module` owner is an imported binding (`ResolveModule`), and anything else is
local (`ResolveLocal`).

Scopes are pushed by the `pre` callback of `Traverse` and popped by the `post`
callback when it returns to the node that pushed them:

- **builtin scope** — pushed first (a `nil`-owner scope holding every builtin
  name), re-established for the program and for each module via `resetToBuiltins`.
- **program / module** — `import`s bring each imported module's public bindings
  into a `*Module`-owner scope; then the module's own public bindings are defined.
- **let** — its bindings are all defined before the bodies are walked, so a
  right-hand side may refer to a later binding or to itself (recursion).
- **lambda case** — the variables in the case's pattern are defined for the body.

A name that is itself a *definition* (a binding name, a pattern variable, an
import) is recorded in a `defining` set when introduced, so the traversal does not
later try to resolve it as a use.

## Errors

Each error is printed immediately with `Log` (located, with the offending source
line) and counts up `Resolution.Errors`:

- **duplicate binding** — `define` finds the name already in the current scope;
  it reports the redefinition and points at the first definition.
- **unbound name** — `resolveName` exhausts the scope stack without a match.
- **unimported module** — a `module.name` whose module is not in the import set.

`main` checks `Resolution.Errors` after resolving; if non-zero it prints
`Analyzer found N errors` and exits before lowering, so a program with a name
error never runs. (The message keeps the historical wording so the diagnostic
output matches the frozen oracle byte-for-byte.)

Modules may import each other circularly (e.g. `core` ↔ `list`); the resolver
handles this because importing a module only brings its *binding names* into
scope — it does not require the module to be resolved first.
